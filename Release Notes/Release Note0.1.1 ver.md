# Release Note0.1.1 ver — 자동 숨김과 복원 위치 수정

배포일: **2026-11-09, 한국 시간**. 제품 버전: **0.1.1**. Git 태그: `v0.1.1`.

**미리보기 배포본입니다.** 실행에 필요한 .NET 런타임을 포함했지만, 트레이 렌더링과 실제 알림 검증에 아래 제한이 남아 있습니다.

## 다운로드와 실행

[GlassDock-TopBar-v0.1.1-win-x64.zip](https://github.com/SeA9612/windows11-top-bar-mac-UI/releases/download/v0.1.1/GlassDock-TopBar-v0.1.1-win-x64.zip)의 전체 압축을 풀고 `GlassDock.TopBar.exe`를 실행합니다. Windows 11 x64용이며 .NET·SDK 설치나 빌드가 필요하지 않습니다. EXE와 같은 폴더의 런타임 파일을 함께 보관하세요.

`v0.1.1` 태그의 `windows11 top bar mac UI/portable/`에도 당시 ZIP이 보존되어 있습니다. 현재 main의 portable 폴더는 최신 실행본을 제공합니다. 소스는 같은 폴더의 `source/`에서 수정할 수 있습니다.

## 새로 적용한 동작

- 선택한 모니터에 최대화·전체 화면 창이 있으면 상단 바를 숨기고 작업 영역 예약을 해제합니다.
- 창을 복원·최소화하면 상단 바를 다시 표시하고 예약 공간을 복원합니다.
- 최대화 중 화면 위쪽 가장자리에 마우스를 약 0.4초 올리면 상단 바가 잠시 나타납니다. 임시 표시 중 배경은 불투명합니다.
- 메뉴·팝업·트레이 사용 중에는 임시 표시를 유지합니다. 트레이 열기 작업이 진행 중인 상태도 숨김 판단에서 제외합니다.
- 숨김·복원 과정에서 기존 트레이 제어기와 알림 감시기를 재생성하지 않습니다.

## 오류 수정

### 최대화 해제 후 상단 바가 28픽셀 내려가는 문제

수정 전 실제 테스트에서는 복원 후 바의 물리 좌표가 `(0,0,1920,28)`에서 `(0,28,1920,56)`으로 밀렸습니다. 예약된 작업 영역이 같다는 이유로 재배치를 생략해, 다시 표시된 실제 창의 좌표 변경을 놓쳤습니다.

이제 예약 영역 캐시와 실제 HWND 좌표를 별도로 비교합니다. `Show` 직후 즉시 위치를 다시 적용하고, 외부 위치 변경 알림에도 재배치를 예약합니다. 표시 여부와 예약 공간뿐 아니라 실제 좌표를 검사하도록 회귀 검사를 확장했습니다.

### 투명 버튼의 클릭 영역

완전히 투명한 픽셀이 Windows의 계층형 창에서 바탕화면 클릭으로 전달될 수 있었습니다. 각 버튼 영역에 최소 알파값을 적용해 아이콘 사이의 빈 부분도 클릭할 수 있게 했습니다. 상단 바 전체의 투명 배경과 테두리 없는 모습은 유지합니다.

## 유지한 기능

Windows 시스템 메뉴, 최근 항목, 창 조작, 실제 전경 앱 이름, 언어·네트워크·음량·배터리·시계·달력과 유리 메뉴를 포함합니다. 종료·재시동·로그아웃은 확인 창을 거칩니다. Explorer 트레이 위치 연동과 Windows 알림 위치 처리 코드는 유지하지만, 최신 표시 검증은 아래와 같이 구분합니다.

## 알려진 문제와 범위

1. 현재 PC에서 트레이 창은 열려도 유리 아이콘이 비거나 `트레이 아이콘을 그리지 못했습니다` / `Live native icon artwork was unavailable` 오류가 관찰됐습니다. 네이티브 아이콘 클릭 영역 6개가 조회돼도 실제 표시의 정상 동작을 보장하지 못합니다. 이 문제를 수정 완료로 기록하지 않습니다.
2. 실제 알림 배너는 최신 재검사에서 나타나지 않았습니다. 배너가 나타나지 않은 원인은 확정하지 않았으며, 사용자의 방해 금지·알림 설정을 바꾸지 않았습니다.
3. 카카오톡 자체 알림의 우상단 위치는 각 PC의 카카오톡 설정에서 선택해야 합니다. 개인 카카오톡 설정이나 대화 데이터는 배포에 포함하지 않습니다.
4. 트레이·알림 내부 창 클래스는 Windows 업데이트에 따라 호환성 수정이 필요할 수 있습니다. 다른 PC, 보조 모니터와 다른 DPI 장치의 실제 화면 검사는 이번 배포에서 수행하지 않았습니다.
5. 키보드 언어는 IME 가/A 상태와 다릅니다. 앱별 파일·편집 메뉴의 범용 이전 기능은 없습니다.

- C# WPF 소스, 상태·좌표·트레이 검증 프로젝트와 빌드 스크립트.
- 기존 독 저장소와 같은 소개·실행 안내·소스·버전별 릴리즈 노트 구조.
- 개인 대화 원문·사용자 화면·개인 설정·실행 로그·빌드 캐시는 제외했습니다.
