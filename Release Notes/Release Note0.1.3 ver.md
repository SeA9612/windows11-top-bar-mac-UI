# Release Note0.1.3 ver — 작업 표시줄 완전 숨김·트레이 열림 오류 수정

배포일: **2026-11-10, 한국 시간**. 제품 버전: **0.1.3**. Git 태그: `v0.1.3`.

[런타임 포함 실행 ZIP 다운로드](https://github.com/SeA9612/windows11-top-bar-mac-UI/releases/download/v0.1.3/GlassDock-TopBar-v0.1.3-win-x64.zip)

ZIP의 전체 압축을 풀고 `GlassDock.TopBar.exe`를 실행합니다. Windows 11 x64용이며 .NET·SDK 설치나 소스 빌드가 필요하지 않습니다. 기존 상단 바가 켜져 있으면 종료한 뒤 새 실행본을 사용하세요. EXE와 런타임 DLL은 같은 폴더에 보관해야 합니다.

## 바뀐 점

### 상단 바가 켜져 있는 동안 Windows 작업 표시줄을 완전히 숨김

자동 숨기기처럼 마우스를 대면 올라오는 방식이 아닙니다. 작업 표시줄을 완전히 숨기고, 그 자리는 화면으로 씁니다. 최대화한 창은 화면 아래 끝까지 찹니다. 앱 실행·전환은 [GlassDock 독](https://github.com/SeA9612/windows11-glass-dock-mac-UI)이 맡습니다.

- 보조 모니터의 작업 표시줄도 함께 숨깁니다.
- 탐색기가 다시 시작되거나 작업 표시줄이 다시 나타나면 곧바로 다시 숨깁니다.
- 작업 영역을 돌려받기 위해 숨기는 동안 Windows 자동 숨기기를 켜 둡니다. 원래 설정은 숨기기 전에 기록해 두고, 종료할 때 그대로 되돌립니다. 원래 자동 숨기기가 켜져 있었다면 켜진 상태로, 꺼져 있었다면 꺼진 상태로 돌아갑니다.
- 상단 바 안내의 "Windows 기본 작업 표시줄은 유지합니다." 문구를 바뀐 동작에 맞게 고쳤습니다.

### 종료할 때 작업 표시줄 복원

| 종료 방식 | 복원 |
|---|---|
| 정상 종료(우클릭 메뉴·트레이 메뉴) | 상단 바가 직접 되돌림 |
| 로그오프·시스템 종료 | 종료 신호를 받는 즉시 되돌림 |
| 작업 관리자 등으로 강제 종료 | 별도 복구 감시 프로세스가 되돌림 |
| "프로세스 트리 끝내기" | 복구 감시가 상단 바의 프로세스 트리 밖에서 실행되므로 함께 종료되지 않고 되돌림 |
| 전원이 꺼지는 등 아무것도 실행되지 못한 경우 | 다음 로그온 또는 다음 실행 때 되돌림 |

숨기는 동안에는 Windows의 `RunOnce`(다음 로그온 때 한 번 실행)에 `GlassDock.TopBar.RestoreTaskbar` 항목을 등록해 둡니다. 정상 복원되면 이 항목은 삭제됩니다. 자동 시작 항목이 아니며, 상단 바를 다시 실행하지 않습니다.

## 오류 수정

### 트레이가 처음부터 상단 바 기준으로 열리지 않던 문제

트레이 화살표를 누르면 약 0.15초 동안 Windows 기본 트레이(밝은 회색 창)가 자체 위치와 펼침 애니메이션으로 먼저 보인 뒤, 상단 바 아래 유리 트레이로 바뀌었습니다. 유리 트레이가 다 준비된 뒤에야 원본 창을 투명하게 만들었기 때문입니다.

- Windows 트레이 창을 화면에 나타나기 전, 또는 처음 나타나는 순간 바로 투명하게 만듭니다.
- 유리 배경을 화살표를 누르는 순간부터 함께 준비합니다.
- Windows의 펼침 애니메이션 도중의 덜 그려진 장면을 쓰지 않습니다. 같은 장면이 연속 두 번 확인돼야 표시합니다.
- 유리 배경과 아이콘을 짧은 페이드(0.12초)로 함께 나타나게 해, 배경만 또는 아이콘만 먼저 보이지 않습니다.

이제 트레이는 처음부터 상단 바 화살표 아래 최종 위치·크기·모습으로 나타납니다. 누른 뒤 표시까지는 약 0.4~0.5초로, 이전 버전과 비슷합니다.

### 트레이를 닫은 뒤 아이콘 툴팁이 화면에 남던 문제

트레이를 Esc로 닫거나 Windows의 툴팁 타이머가 늦게 실행되면, 앱 이름 툴팁(예: "Claude")이 트레이 없이 화면 구석에 남을 수 있었습니다. 닫을 때 트레이에 딸린 툴팁을 숨깁니다. 상단 바가 켜져 있는 동안에는 뒤늦게 나타나는 툴팁도 계속 숨깁니다.

### 강제 종료 후 작업 표시줄이 돌아오지 않을 수 있던 문제

복구 감시 프로세스가 상단 바의 하위 프로세스였기 때문에, 프로세스 트리째 강제 종료되면 감시도 함께 종료되어 작업 표시줄이 숨겨진 채로 남을 수 있었습니다. 감시를 프로세스 트리 밖에서 실행하고, 다음 로그온 복원 항목을 추가했습니다. 트레이를 연 상태에서 강제 종료돼 작업 표시줄이 투명하게 남는 경우도 감시가 정리합니다.

## 배포와 남은 범위

이번 배포도 **미리보기 배포본**입니다. 다음 항목은 이번에 실제로 확인하지 못했습니다.

- 보조 모니터 작업 표시줄 숨김(단일 모니터 PC라 코드로만 처리)
- 탐색기 재시작 후 다시 숨기기
- 실제 로그오프·재부팅 후 복원(로그온 복원 항목의 등록·삭제까지만 확인)
- 수정 후 Windows 알림 배너 재검사(화면 자동 조작 중 Windows가 배너를 막아 재검사하지 못함. 작업 표시줄 숨김 직후의 실제 화면 확인은 통과)
- 다른 PC·DPI 조합, 실제 카카오톡 알림 수신

0.1.2 릴리즈와 태그는 당시 기록으로 유지합니다. 개인 설정·로그·대화·사용자 화면과 인수인계 자료는 공개 업로드에 포함하지 않습니다.
