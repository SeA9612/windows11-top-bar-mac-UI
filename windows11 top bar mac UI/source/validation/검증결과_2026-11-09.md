# 최대화 해제 후 위치 오류 수정 결과

## 재현과 수정

수정 전 실제 테스트 창을 최대화한 후 복원하면 상단 바 HWND 좌표가 `(0,0,1920,28)`에서 `(0,28,1920,56)`으로 변경됐다. 기존 검사는 표시 여부와 작업 영역만 확인해 이 오류를 검출하지 못했다.

AppBarHost는 예약 영역 캐시와 별도로 실제 HWND 좌표를 비교해 수정한다. TopBarWindow는 Show 직후 위치를 다시 적용한다. 외부 위치 변경 알림에도 재배치를 예약한다. 트레이 열기 작업이 진행 중일 때는 상단 바의 임시 표시를 유지한다. 투명 버튼의 빈 픽셀이 바탕화면 클릭으로 처리되는 문제는 버튼 영역에 최소 알파값을 적용해 보완했다. 상단 바 전체 배경은 기존 투명 상태를 유지한다.

## 통과

- 기존 상태·좌표·Win32 ABI 42개 검사.
- 초기 위치, 의도적으로 28픽셀 밀어낸 후 위치 복구.
- 최대화·복원 6회 반복 후 매번 `(0,0,1920,28)` 유지.
- 작업 영역 예약 해제·복원, 중복 예약 없음.
- 전체 화면 진입·해제, 최소화 후 표시와 좌표 유지.
- 숨김·복원 전후 동일한 트레이 제어기와 알림 감시기 유지.
- Release 빌드 및 런타임 포함 배포본 생성.
- computer-use로 실제 버튼 중앙 클릭이 상단 바에 전달되는 것 확인.

위치 회귀 검사:

```powershell
$env:GLASSDOCK_POSITION_ONLY='1'
dotnet run --project validation/AutoHide/AutoHideTests.csproj -c Release
```

## 미해결 또는 확인 불가

- 트레이 통합 검사에서 `트레이 아이콘을 그리지 못했습니다` 또는 `Live native icon artwork was unavailable`이 재현됐다. 실제 화면 확인에서도 빈 트레이 유리 화면이 관찰됐다. 6개 네이티브 아이콘 클릭 영역은 조회됐지만 화면 표시의 정상 여부를 보장하지 못한다. 이번 위치 수정에 실험적인 트레이 렌더링 대체 코드는 포함하지 않았다. 기존 렌더링 경로를 유지한다.
- 알림 감시기의 유지 여부는 통과했지만, 실제 테스트 알림 배너가 재검사 시 표시되지 않아 알림 수신·배치 검사는 실패했다. Windows가 배너를 표시하지 않은 원인은 확정하지 않았다. 알림이나 방해 금지 설정을 변경하지 않았다.
- 보조 모니터 및 다른 DPI의 실제 장치 검사는 수행하지 않았다.

실행본: `artifacts/topbar-portable/GlassDock.TopBar.exe`. 11월 6일 ZIP은 이전 버전의 보관본으로 이번 변경을 포함하지 않는다.
