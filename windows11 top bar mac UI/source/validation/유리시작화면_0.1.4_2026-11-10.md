# 유리 시작 화면 — 0.1.4

검증일: 2026-11-10, 한국 시간. Windows 11 25H2(빌드 26200), 1920×1080 단일 모니터, 100% 배율 PC에서 확인했습니다.

## 기능

- Windows 키를 혼자 눌렀다 떼면 기본 시작 메뉴 대신 화면 가운데에 유리 시작 화면이 열립니다. 다시 누르면 닫힙니다.
- 구성: 위쪽 검색창, 아래 범주 칸 4열(생산성, 유틸리티 및 도구, 개발자 도구, 기타, 창의성, 게임, 엔터테인먼트).
  - 칸 안의 앱 아이콘을 누르면 바로 실행합니다.
  - 칸이나 칸 이름을 누르면 그 범주의 앱 전체를 보여 줍니다.
- 검색: 이름 앞부분 일치 → 단어 앞부분 일치 → 이름 일부 일치 → 앱 ID 순으로 정렬합니다. Enter로 실행하고 방향키로 고릅니다.
- 닫기:
  - Esc는 검색 지우기 → 범주에서 돌아가기 → 닫기 순으로 동작합니다.
  - 다른 창을 누르면 닫힙니다.
  - 열리는 순간에 다른 창이 포커스를 가져간 경우에도 닫힙니다.
- 디자인: 독과 같은 유리 재질(Composition 흐림, 옅은 색조, 가장자리 반사, 그림자)입니다.
  - 창 높이는 범주 줄 수에 맞춥니다.
  - 뒤 화면 밝기를 0.4초마다 다시 읽어 글자색과 칸 색을 바꿉니다(흰 배경 254 → 어두운 글자, 검은 배경 11 → 흰 글자).
- Windows 키 처리:
  - 저수준 키보드 훅이 Windows 키를 혼자 눌렀다 뗀 경우만 가로챕니다. 사이에 미할당 키를 끼워 넣어 기본 시작 메뉴가 열리지 않게 합니다.
  - Win+E 같은 조합 키는 그대로 Windows로 갑니다.
  - Ctrl+Esc는 기본 시작 메뉴를 엽니다.
  - 상단 바를 종료하면 훅도 해제됩니다.
- 앱 목록: Windows의 앱 폴더(`shell:AppsFolder`)에서 읽습니다.
  - 웹 링크, 도움말, 제거 프로그램은 뺍니다.
  - Windows 도구(System32 관리 도구 등)는 범주 화면에 넣지 않지만 검색에는 나옵니다.
  - 범주 분류는 Windows가 공개하지 않으므로 이름과 앱 ID 규칙으로 정합니다.
  - 정렬은 Windows처럼 영문 이름(A–Z)이 먼저, 한글(ㄱ–ㅎ)이 다음입니다.

## 기본 시작 메뉴 감지 방법

이 Windows에서는 시작 메뉴 창이 `EnumWindows`에 나오지 않습니다. 닫힌 뒤에도 창 상태(보임·숨김·위치)가 그대로라, 일반 창 정보로는 열림을 판단할 수 없습니다. 그래서 검사는 화면 아래쪽 띠(560,860–1360,1040)에 분홍(#FF00FF) 단색 캔버스를 깔고, 15개 지점의 픽셀이 바뀌는지로 판단합니다.

- 매 실행 맨 앞에서 Ctrl+Esc로 기본 시작 메뉴를 실제로 열어 감지기를 확인합니다.
- 결과: 열림 15/15 다름, 닫힘 0/15 다름, 유리 시작 화면만 떠 있을 때 0/15 다름.

## 확인한 항목

| 항목 | 결과 |
|---|---|
| 단위 검사(분류·검색·정렬·목록 제외 규칙 포함) | 72개 통과 |
| 유리 시작 화면 통합 검사 | 35개, 연속 5회 통과 |
| 검사 내용 | 감지기 대조, 가운데 위치, 크기, 유리 배경, 범주 7개·아이콘, 검색, Esc 단계, 다른 창 활성화·열리는 중 포커스 이동 시 닫힘, 배경 밝기에 따른 글자색, Win 키 열기·닫기, 기본 시작 메뉴 안 열림, 포커스·검색창 입력, Win+다른 키 통과, Windows 키 눌림 상태 안 남음, Ctrl+Esc 통과, 앱 실행 |
| 기존 검사 | 작업 표시줄 16개, 트레이, 최대화 자동 숨김 통과 |
| 실제 화면 | 배포 빌드에서 Windows 키 열기·닫기, "note"·"메모" 검색, 범주 클릭, Esc 단계 확인 |

외부 간섭(검사 중 다른 곳에서 들어온 Esc나 다른 창 활성화)이 있으면 시작 화면이 정상적으로 닫혀 검사가 실패할 수 있습니다. 간섭 없이 12회 연속 통과했고, 간섭을 일부러 넣었을 때만 실패가 재현됐습니다. 그래서 키를 누르는 검사는 이름 있는 뮤텍스 `Global\GlassDock.InputTests`로 동시 실행을 막습니다.

## 확인하지 못한 항목

- 관리자 권한 창이 맨 앞에 있을 때(Windows 보안 규칙상 우리 입력이 막혀 기본 시작 메뉴가 열릴 수 있음)
- 보조 모니터, 다른 배율, 다른 PC
- 처음 보는 앱의 범주(규칙에 없으면 "기타")

```powershell
dotnet run --project validation/TopBar/TopBarTests.csproj -c Release
dotnet run --project validation/Start/StartTests.csproj -c Release
```

실제 상단 바를 종료하고, 검사 중에는 키보드·마우스를 건드리지 마세요.
