# GlassDock 상단 바 — 실행·수정 안내

최종 정리: 2026-11-09 (한국 시간)
Windows 11 x64에서 독과 별도로 실행되는 WPF 상단 바입니다.

현재 로컬 버전: **0.1.4**. Windows 키로 화면 가운데에 유리 시작 화면이 열리도록 추가했습니다. 최신 검사 결과는 `validation/유리시작화면_0.1.4_2026-11-10.md`입니다. 0.1.3 작업 표시줄 숨김·트레이 수정 기록은 `validation/작업표시줄숨김_트레이수정_0.1.3_2026-11-10.md`에 있습니다. 0.1.2 트레이 수정 기록은 `validation/트레이수정_0.1.2_2026-11-09.md`에 보존했습니다.

## 실행

배포 ZIP을 모두 풀고 `실행파일\GlassDock.TopBar.exe`를 실행합니다.
실행파일 폴더에는 .NET 8 Desktop Runtime이 포함되어 있으므로 별도 런타임 설치가 필요하지 않습니다. 폴더 안의 파일을 함께 보관하고 이동하세요.
상단 바 우클릭 메뉴 또는 Windows 트레이의 `GlassDock 상단 바 → 상단 바 종료`로 종료할 수 있습니다. 자동 시작 등록은 하지 않습니다.

## 최종 동작

- 높이 28 DIP. 일반 창·바탕화면에서는 선택한 모니터 위쪽에 작업 영역을 예약합니다.
- 그 모니터에 보이는 최대화·전체 화면 창이 있으면 상단 바를 숨기고 작업 영역 예약도 해제합니다. 창을 복원·최소화하면 상단 바와 작업 영역 예약이 돌아옵니다.
- 최대화 중 화면 위쪽 가장자리에 마우스를 약 0.4초 올리면 상단 바가 잠시 나타납니다. 트레이나 메뉴를 사용하는 동안 유지하며, 마우스가 떠나고 열린 팝업이 닫히면 다시 숨습니다. 임시 표시 중 배경은 불투명합니다.
- 최대화·전체 화면 창이 없으면 일반 창·최소화·바탕화면 상태에서 배경은 완전 투명합니다.
- Windows 버튼: PC 정보, 설정, Microsoft Store, 최근 항목, 작업 관리자, 절전, 재시동, 종료, 화면 잠금, 로그아웃 메뉴입니다. 재시동·종료·로그아웃은 확인 창을 거칩니다.
- 앱·창 메뉴, 실제 전경 앱 이름, 키보드 언어, 네트워크, 음량·음소거, 배터리, 날짜·시간과 달력을 제공합니다.
- 트레이 화살표를 누르면 Windows의 숨겨진 아이콘 창이 상단 바 아래에 표시됩니다. 바깥 클릭·Esc·화살표 재클릭으로 닫습니다. 작업 표시줄에 고정된 아이콘을 숨겨진 아이콘에 강제로 추가하지 않습니다.
- 메뉴·하위 메뉴·패널·트레이는 독과 같은 투명 유리 색조, Windows Composition 흐림, 가장자리 반사와 그림자를 사용합니다. 글자는 배경 밝기에 맞춰 조정하며 분홍색 선택 효과는 없습니다.
- 상단 바가 켜져 있는 동안 Windows 작업 표시줄(보조 모니터 포함)을 완전히 숨기고 그 자리를 화면으로 씁니다. 앱 실행·전환은 독이 맡습니다. 탐색기가 다시 시작되거나 작업 표시줄이 다시 나타나면 곧바로 다시 숨깁니다.
- 작업 영역을 돌려받기 위해 숨기는 동안 Windows 자동 숨기기를 켜 둡니다. 원래 설정은 `%LOCALAPPDATA%\GlassDock\taskbar-state.json`에 먼저 기록합니다. 정상 종료·로그오프 때 원래 설정으로 되돌립니다. 강제 종료 때는 별도 감시 프로세스가 되돌립니다. 감시 프로세스는 상단 바의 프로세스 트리 밖에서 실행되므로 작업 관리자의 "프로세스 트리 끝내기"로 함께 종료되지 않습니다. 숨기는 동안에는 `HKCU\...\RunOnce`에 `GlassDock.TopBar.RestoreTaskbar` 항목을 등록해 둡니다. 전원이 꺼지는 등 아무것도 복원하지 못한 경우에도 다음 로그온 때 한 번 실행되어 작업 표시줄을 되돌립니다. 정상 복원되면 이 항목은 삭제됩니다.
- Windows 키를 혼자 눌렀다 떼면 기본 시작 메뉴 대신 화면 가운데에 유리 시작 화면이 열립니다(다시 누르면 닫힘). 위쪽 검색창과 범주 칸 4열(생산성·유틸리티 및 도구·개발자 도구·기타·창의성·게임·엔터테인먼트)로 구성되고, 칸 안 아이콘을 누르면 바로 실행, 칸을 누르면 그 범주의 앱 전체가 보입니다. 독과 같은 유리 재질이며, 뒤 화면 밝기에 따라 글자색이 바뀝니다. Win+E 같은 조합 키는 그대로 동작하고 Ctrl+Esc는 기본 시작 메뉴를 엽니다. 앱 목록은 Windows의 앱 폴더(shell:AppsFolder)에서 읽고, 범주는 Windows가 공개하지 않아 이름·앱 ID 규칙으로 분류합니다(`src/TopBar/StartCatalog.cs`).
- Windows 기본 알림 배너는 상단 바 오른쪽 아래에 표시되도록 위치를 조정합니다. 상단 바가 숨겨져 있어도 알림 감시와 오른쪽 위 배치는 계속 작동합니다. 메시지 내용이나 발신자를 읽거나 저장하지 않습니다.

## 다른 PC에 적용할 때

- 권장 환경: Windows 11 x64. 이 PC에서는 Windows 11 25H2, 빌드 26200에서 검증했습니다.
- 실행파일 폴더 전체를 옮겨 실행합니다. 기존 독이 없어도 상단 바는 독립 실행됩니다. 독 자체 실행파일은 이 패키지에 포함하지 않습니다.
- 첫 실행은 주 모니터에 표시합니다. 상단 바 우클릭의 모니터 메뉴에서 변경할 수 있습니다.
- 카카오톡 자체 알림은 각 PC에서 `카카오톡 설정 → 알림 → 표시 위치 → 화면 우상단`으로 선택하세요. 현재 PC의 카카오톡 설정이나 대화 데이터는 배포에 포함하지 않습니다.
- 설정은 `%LOCALAPPDATA%\GlassDock\topbar.json`, 오류 기록은 같은 폴더의 `topbar-errors.log`에 생성됩니다. 다른 PC의 모니터 ID가 섞이지 않도록 개인 설정 파일은 패키지에 포함하지 않았습니다.

## 수정하고 빌드하기

`소스` 폴더를 VS Code로 열고 .NET 8 SDK 이상을 설치합니다. 최초 빌드는 NuGet 패키지와 Windows 대상 팩 복원을 위해 인터넷 연결이 필요할 수 있습니다.

```powershell
dotnet run --project src/TopBar/TopBar.csproj
dotnet run --project validation/TopBar/TopBarTests.csproj -c Release
powershell -ExecutionPolicy Bypass -File .\Build-TopBar.ps1
```

빌드 스크립트의 기본 결과는 런타임 포함 `artifacts/topbar-portable`입니다. 런타임을 별도로 설치하는 작은 배포본은 `Build-TopBar.ps1 -FrameworkDependent`로 만들며 `artifacts/topbar-small`에 생성됩니다.

## 주요 수정 위치

- `src/TopBar/TopBarWindow.cs`: 상단 바 구성, 메뉴, 패널, 버튼 동작.
- `src/TopBar/BarBackground.cs`: 창 상태에 따른 배경 불투명도.
- `src/TopBar/TopBarWindow.cs`, `AppBarHost.cs`: 최대화 자동 숨김·가장자리 임시 표시·작업 영역 해제 및 복원.
- `src/TopBar/App.xaml`: 메뉴·버튼 템플릿과 선택 효과.
- `src/TopBar/Glass/GlassTheme.cs`: 유리 색조, 흐림 강도, 반사·그림자 수치.
- `src/TopBar/Glass/GlassPopup.cs`: 팝업 유리 배경과 글자 색 조정.
- `src/TopBar/TrayOverflowHost.cs`, `Glass/TrayGlassWindow.cs`: 네이티브 트레이 위치·표시·입력 유지.
- `src/TopBar/Glass/NativeTrayOpacity.cs`: 트레이 원래 스타일 복원과 종료 복구 감시.
- `src/TopBar/NotificationPositionHost.cs`: Windows 알림 배너 위치.
- `src/TopBar/AppBarHost.cs`: 화면 위쪽 작업 영역 예약.
- `src/TopBar/StartKeyHook.cs`, `StartMenuWindow.cs`, `StartCatalog.cs`, `StartApps.cs`: Windows 키 가로채기, 유리 시작 화면, 앱 분류·검색, 앱 목록·아이콘.
- `src/TopBar/TaskbarHider.cs`: Windows 작업 표시줄 숨김, 원래 자동 숨기기 설정 기록·복원, 강제 종료 복구 감시.

## 검증과 범위

2026-11-09 위치 수정 당시의 검증과 제한은 `validation/검증결과_2026-11-09.md`에 보존했습니다. 그때 남아 있던 트레이 표시 오류는 0.1.2에서 수정하고 실제 아이콘 그림·입력 대상·앱 콜백·재열기를 검사했습니다. 실제 알림 수신 재검사의 기존 제한은 별개입니다. 0.1.3의 작업 표시줄 숨김·트레이 열림 수정 검사는 `validation/작업표시줄숨김_트레이수정_0.1.3_2026-11-10.md`에 있습니다.

작업 표시줄 숨김·복원 통합 검사는 다음과 같습니다. 실행 중인 상단 바를 종료한 상태에서 실행하세요. 검사가 끝나면 원래 자동 숨기기 설정으로 되돌립니다.

```powershell
dotnet run --project validation/Taskbar/TaskbarTests.csproj -c Release
```

유리 시작 화면 통합 검사는 다음과 같습니다. 실행 중인 상단 바를 종료하고, 실행 중에는 키보드·마우스를 건드리지 마세요(Windows 키·Ctrl+Esc·Esc를 직접 보냅니다). 기본 시작 메뉴가 열렸는지는 화면 아래쪽 띠에 깐 단색 캔버스의 픽셀이 바뀌는지로 판단하고, 맨 앞에서 Ctrl+Esc로 이 감지기를 먼저 확인합니다. 이 Windows 11 25H2에서는 시작 메뉴 창이 창 목록에 나오지 않고 닫혀도 창 상태가 바뀌지 않아 일반 창 정보로는 판단할 수 없기 때문입니다.

```powershell
dotnet run --project validation/Start/StartTests.csproj -c Release
```

42개 상태·배치·Win32 ABI 검사와 네이티브 트레이의 위치, 아이콘 클릭 영역, 투명 그림, 외부 포커스 닫기, 재열기, 원래 위치·스타일 복원 및 복구 감시 경로를 확인했습니다. 밝은 배경과 어두운 배경의 메뉴·하위 메뉴도 표시 확인했습니다.

실제 데스크톱을 사용하는 트레이 통합 검사는 다음과 같습니다. 열린 트레이가 없는 상태에서 실행하세요. 트레이를 6번 열면서 1ms 간격으로 Windows 기본 트레이(밝은 회색 원본 창)가 화면에 드러나는지 확인하고, 닫은 뒤 트레이 아이콘 툴팁이 화면에 남는지도 확인합니다.

```powershell
dotnet run --project validation/Tray/TrayTests.csproj -c Release
```

자동 숨김 통합 검사는 별도 테스트 창을 최대화·전체 화면·복원·최소화하고, 실제 트레이를 열어 숨김 중 유지와 재열기를 확인합니다. 실행 중인 상단 바를 종료한 상태에서 실행하세요. `GLASSDOCK_NOTIFICATION_TEST=1`을 설정하면 자체 테스트 알림을 띄워 숨김 중 배치도 검사합니다. 방해 금지 등으로 배너가 차단된 환경에서는 알림 검사가 실패할 수 있습니다.

```powershell
dotnet run --project validation/AutoHide/AutoHideTests.csproj -c Release
```

Windows 기본 테스트 알림의 위치를 확인했고, 카카오톡의 우상단 표시 설정을 확인했습니다. 카카오톡 실제 수신 메시지를 보내거나 수신 테스트를 진행하지는 않았습니다.

트레이·알림 위치 조정은 Windows 내부 창 클래스에 의존하므로 Windows 업데이트에 따른 호환성 수정이 필요할 수 있습니다. Windows 기본 알림 호스트는 한국어·영어 제목을 대상으로 합니다. 앱 자체 알림은 해당 앱의 위치 설정을 사용합니다. 방해 금지나 앱의 알림 비활성화를 강제로 해제하지 않습니다. 독점 전체 화면에서는 Windows 앱바 규칙에 따라 상단 바가 뒤로 갈 수 있습니다.

키보드 언어 표시는 실제 IME의 가/A 모드와 다릅니다. 앱별 파일·편집 메뉴를 옮기는 범용 연동은 구현하지 않았습니다.
